# Vela — 3D Combat Feel Prototype (Unity 6 LTS)

A fast, ugly-on-purpose 3D prototype in the spirit of Ragnarok Online / Trickster:
capsules and boxes, isometric camera, and a combat loop you can actually *feel*.
Three attack moves, a dodge roll with i-frames, three monsters that each want you to
play differently, loot that drops off corpses, and a HUD that narrates every single
event so you can see exactly what the game thinks just happened.

Everything is plain text (C# + project config). The scene is generated by an editor
script, so there are no binary/YAML assets to go stale and nothing to merge.

---

## Quick start

1. Install **Unity Hub** → current **6000.0 LTS** editor (`ProjectSettings/ProjectVersion.txt`
   pins `6000.0.32f1`; any 6000.0.x is fine).
2. Unity Hub → *Add* → *Add project from disk* → this repo root.
3. Wait for the first import, then menu bar → **Vela ▸ Build Prototype Scene**.
   That generates `Assets/Scenes/Prototype.unity` plus materials, and adds it to Build Settings.
4. Press **Play**. Press **H** for the in-game controls overlay.

Re-run the menu item any time for a clean arena.

## Controls

| Input | Action |
| --- | --- |
| `WASD` / arrows | Move (camera-relative) |
| `Space` / `Shift` | **Dodge roll** — i-frames, cancels any attack |
| `J` / left mouse | **Move 1 — Slash**: fast, 120° arc, 3-hit chain, 3rd swing is a knockback finisher |
| `K` / right mouse | **Move 2 — Lunge Thrust**: dashes forward, narrow arc, 2 damage — the gap closer |
| `L` / middle mouse | **Move 3 — Spin Smash**: slow 360° heavy, 3 damage, big knockback + stagger |
| `F` | Pick up the item you are standing on |
| `Q` / `E` | Rotate camera 45° |
| `H` | Toggle the controls overlay |
| `R` | Restart |

## The three monsters (one map, three fights)

They sit on three coloured floor pads so you can walk to whichever one you want to test.

| | **Rusher** (red, north-west) | **Caster** (violet, north-east) | **Brute** (blue, south-east) |
| --- | --- | --- | --- |
| HP | 4 | 3 | 14 |
| Style | Aggressive melee | Ranged kiter | Armoured tank |
| Threat | Stops, flashes yellow, then lunges in a **locked direction** | Holds ~7.5 m, fires slow orbs, every 2nd cast is a 3-orb fan, **blinks** when you get close | Huge telegraphed **ground slam** (1.15 s wind-up, 4.4 m ring) |
| How you beat it | Roll *through* the lunge, hit it in the 1 s recovery | Close the distance with the Lunge Thrust; sidestep or roll the orbs | It takes 75 % less damage across its **front arc** — roll behind it and hit its back during the 1.8 s exhausted window |
| Teaches | Dodge timing | Spacing and gap closing | Positioning |

Monsters respawn after a few seconds so you can keep testing without restarting.
Drop a monster's `respawnSeconds` to 0 if you want it gone for good.

## What you get as feedback (this is the point of the prototype)

**When you hit something**
- Hit-stop — the whole game freezes for 40–110 ms, scaled to how heavy the move is
- Camera shake, scaled the same way
- White flash on the monster, knockback along the blow's direction
- Floating damage number, plus a line in the event feed (`FINISHER Slash hit Rusher for 2`)
- A spark at the contact point and a swing/ring effect for the move itself
- Heavy hits (Spin Smash, chain finisher) **stagger** the monster for 0.4 s

**When you get hit**
- Red screen flash, camera shake, knockback, hit-stop
- `-1` popup over your head and a feed line naming the attack that landed
- Your HP bar drops a segment; below 34 % HP the screen edges pulse red

**When you dodge**
- Rolling shows a ring and the HUD reads `ROLLING — I-FRAMES`
- If i-frames eat an attack it is a **PERFECT DODGE**: slow-motion for 0.35 s, a flash,
  the dodge cooldown is refunded, and your next hit gets +1 damage (`FOCUS`)

**When a monster dies**
- Hit-stop, shake, a burst ring, `DEFEATED` popup, and it shrinks away
- It drops 1–7 items that pop out in an arc and land on the floor

**When you pick something up**
- Walk near a drop → `[F] Pick up Red Potion` prompt
- On pickup: ring effect, `Red Potion (+1 HP)` popup, feed line, green screen flash for heals
- Drops blink and expire after 30 s

## HUD

- **Top-left** — segmented HP bar, dodge cooldown bar (`DODGE READY` / `ROLLING — I-FRAMES`), `FOCUS` timer
- **Top-right** — time, kills, items, score
- **Bottom-centre** — the three moves with cooldown fills, damage, and key bindings; the slash chain shows combo pips and `FINISHER READY`
- **Bottom-left** — the event feed: every hit, dodge, drop, pickup, respawn
- **Over each monster** — name, HP bar, and its current phase in plain words
  (`WIND-UP — dodge!`, `CASTING — sidestep!`, `EXHAUSTED — hit its back!`, `FRONT ARMOUR — flank it`)
- **On death** — `YOU DIED` with your run stats and `R` to restart

It is all IMGUI (`OnGUI`) in one file — no canvas, no fonts, no prefabs, and every
number on screen is a line of code you can change.

## Tuning the feel

Select an object in the Hierarchy and edit its component — that is what a prototype is for.

- **Player ▸ PlayerCombat** — each of the three moves has `windup` / `active` / `recovery` /
  `cooldown`, `range`, `arcDegrees`, `damage`, `knockback`, `hitstop`, `shake`, `lungeSpeed`,
  `moveScale` (how much you can walk while swinging). Also `comboWindow`, `comboLength`,
  `finisherBonusDamage`, `inputBufferSeconds`.
- **Player ▸ IsometricPlayerController** — `dodgeSpeed`, `dodgeDuration`, `dodgeCooldown`,
  `dodgeInvulnerabilityBonus` (widens or tightens the dodge window),
  `perfectDodgeSlowMotion`, `focusWindowSeconds`, move/accel/turn speeds.
- **Player ▸ Health** — `maxHealth` (the bar follows it), `invulnerabilityAfterHit`.
- **Player ▸ PlayerPickup** — `pickupRadius`, `autoPickup` (walk-over pickups instead of `F`).
- **Monster_N ▸ RusherMonster / CasterMonster / BruteMonster** — the per-variant numbers:
  `windupSeconds` is the single most important one in the whole project, it *is* the dodge
  window. The Brute's `armorArcDegrees` / `armorReduction` decide how hard flanking is.
  Select a monster to see its ranges drawn as gizmos.
- **Monster_N ▸ LootDropper** — one row per item type: chance, min/max count.
- **Main Camera ▸ IsometricCameraRig** — `distance`, `pitch`, `yaw`, `followSmoothTime`.
  Orthographic `size 10` is what gives the flat isometric read.
- **GameManager ▸ PrototypeGameManager** — `showHud`, `showHelpAtStart`, flash and feed timing.

Changes made during Play mode are discarded when you stop — tune in Edit mode.

## How the combat actually works

- **`Health` is the referee.** Every blow is a `DamageInfo` (amount, team, direction,
  knockback, hit-stop, shake, label). `Apply()` refuses same-team damage, turns a hit into a
  **dodge** when i-frames are up, and runs an optional `IncomingDamageFilter` — which is the
  entire Brute front-armour mechanic in one delegate. The victim reacts to its own `Damaged`
  event, so attackers never need to know what they hit.
- **The dodge is one line.** Rolling calls `GrantInvulnerability(dodgeDuration + bonus)`.
  If an attack is refused *while rolling*, that is a perfect dodge.
- **Monsters commit.** Every attack locks its direction at the end of the wind-up, so the
  monster can be sidestepped or rolled through. Tracking slowly during the wind-up stops
  walking backwards from being a free answer. That commitment is the whole reason the
  fights are readable.
- **Attack hitboxes** are an `OverlapSphere` plus an angle test against the arc, swept every
  frame of the active window with a per-swing "already hit" list — so a swing lands once per
  target but still catches something walking into it.
- **No NavMesh, no animation, no prefabs.** Monsters steer directly and slide along obstacles
  with their `CharacterController`; effects are primitives that fade and delete themselves.

## Known rough edges

- The scripts are compile-checked against an API stub, not against a real Unity editor
  (there is no Unity install in the environment they were written in). If the Console
  reports something on first import it will be small — fix and commit.
- No animation: everything reads through colour, scale and primitive effects.
- No win condition — it is a test arena. Kills, items and score are just counters.
- Never commit `Library/`, `Temp/`, `Logs/` or `Builds/` — `.gitignore` covers them.
