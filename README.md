# Vela — 3D Isometric Prototype (Unity 6 LTS)

A minimal, playable 3D isometric prototype: move a character around a walled arena
with an orthographic isometric camera, dash, rotate the camera in steps, and collect
shards against a timer.

Everything here is plain text (C# + project config). The scene itself is generated by
an editor script, so there are no hand-written binary/YAML assets to go stale.

---

## Step 1 — Install Unity

1. Install **Unity Hub** from https://unity.com/download
2. In Hub → *Installs* → *Install Editor*, pick the current **6000.0 LTS** release.
3. Add the build-support module for your platform (Windows/Mac/Linux Build Support).

`ProjectSettings/ProjectVersion.txt` pins `6000.0.32f1`. If you install a different
6000.0.x patch, Unity Hub will offer to open it with your version — that is fine and
it will rewrite that file.

## Step 2 — Open this repo as a project

1. Clone the repo (you already have it if you're reading this locally).
2. Unity Hub → *Add* → *Add project from disk* → select the repo root (the folder
   containing `Assets/`, `Packages/`, `ProjectSettings/`).
3. Open it. First import takes a few minutes while Unity builds `Library/`
   (which is git-ignored — never commit it).

## Step 3 — Generate the prototype scene

There is no committed `.unity` scene file. Build it from the menu:

1. Wait for compilation to finish (no red errors in the Console).
2. Menu bar → **Vela → Build Prototype Scene**.
3. This creates `Assets/Scenes/Prototype.unity`, creates materials under
   `Assets/Materials/`, and adds the scene to Build Settings.

Re-run that menu item any time you want a clean arena back.

## Step 4 — Play it

Press **Play**. Controls:

| Input | Action |
| --- | --- |
| `WASD` / arrows | Move (relative to the camera, so "up" is always up-screen) |
| `Space` | Dash |
| `Q` / `E` | Rotate camera 45° left / right |
| `R` | Restart the scene |

Collect all 7 shards; the HUD shows count, score and elapsed time.

## Step 5 — Tune the feel

Select the objects in the Hierarchy and edit the inspector values — this is where a
prototype earns its keep:

- **Player** → `IsometricPlayerController`: `moveSpeed`, `acceleration`,
  `deceleration`, `turnSpeedDegrees`, dash speed/duration/cooldown, `gravity`.
- **Main Camera** → `IsometricCameraRig`: `distance`, `pitch`, `yaw`,
  `followSmoothTime`, `yawStepDegrees`. Camera is orthographic (`orthographicSize 9`)
  — that is what gives the flat isometric read; switch it to perspective to compare.
- **Shard_N** → `Collectible`: `scoreValue`, spin and bob values.

Changes made during Play mode are discarded when you stop — tune in Edit mode, or
copy the component values before stopping.

## Step 6 — Build a player

`File → Build Settings` → pick your platform → *Build*. `Prototype.unity` is already
scene 0. Output goes to `Builds/` (git-ignored).

## Project layout

```
Assets/
  Editor/
    PrototypeSceneBuilder.cs     Vela ▸ Build Prototype Scene (arena, player, camera, shards)
  Scripts/
    Core/VelaInput.cs            Input facade; works with legacy Input or the Input System package
    Player/IsometricPlayerController.cs   CharacterController movement, camera-relative, dash
    Camera/IsometricCameraRig.cs Orthographic follow rig with stepped yaw rotation
    Gameplay/Collectible.cs      Trigger pickup, spin + bob
    Gameplay/PrototypeGameManager.cs   Score, timer, IMGUI HUD, restart
Packages/manifest.json           Built-in render pipeline, no extra dependencies
ProjectSettings/ProjectVersion.txt
```

`Assets/Scenes/` and `Assets/Materials/` are generated by step 3.

## How the isometric bits work

- **Camera-relative movement.** Input is rotated by the camera's yaw before being
  applied (`IsometricPlayerController.CameraRelative`), so pressing *up* always moves
  up-screen, even after `Q`/`E` rotates the view.
- **Orthographic projection.** No perspective convergence, so the arena reads as a
  clean isometric grid. Pitch 35° / yaw 45° is a classic game-iso angle (true
  isometric is ~35.264°/45°).
- **Stepped camera rotation.** Yaw snaps in 45° steps but lerps to the new angle, so
  the world stays readable while the turn feels smooth.

## Notes

- The scripts have not been compiled in CI — there is no Unity install in the
  environment they were authored in. If the Console reports an error on first import,
  it will be a small one; fix and commit.
- Never commit `Library/`, `Temp/`, `Logs/`, or `Builds/` — `.gitignore` covers them.
- `.gitattributes` sets up `unityyamlmerge` for scene/prefab merges; configure it with
  `git config merge.unityyamlmerge.driver` if you start committing scenes.
